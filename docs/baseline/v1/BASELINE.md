## 2. 当前产品定位

当前版本是一个面向中国沿海居民的移动优先台风实况与预警信息页。它试图帮助用户快速回答：

1. 现在是否有活动台风；
2. 台风在哪里、强度如何；
3. 台风接下来往哪里移动；
4. 当前预警意味着什么、用户应该做什么。

安全边界：网站只转述公开来源的台风实况、路径预测和预警信息，不自行发布气象预报或预警，最终以当地气象台和政府部门信息为准。

## 3. 目标用户与核心场景

### 主要用户

- 居住或工作在中国东南沿海城市、需要快速判断台风影响的普通居民；
- 需要替家人查看风险、转发权威信息的人；
- 出行、通勤或临时安排受台风影响的人。

### 核心使用场景

- 用户从社交平台或搜索进入，在 30 秒内判断“这场台风和我有没有关系”；
- 用户查看当前位置附近的风险、预警级别和防御建议；
- 用户查看实况路径和未来预测，了解时间与方向；
- 数据异常或延迟时，用户仍能明确知道信息来源、更新时间和应前往的权威渠道。

## 4. 当前已有功能

- 自动识别并展示活动台风；没有活动台风时回退展示最近停止编号的台风；
- 展示中英文名称、编号、中心位置、中心气压、风力、风速、移动方向与速度；
- 展示实况路径和未来预测路径；
- 展示来源系统预警状态、防御提示入口和信息来源；
- 提供 72/48/24 小时时间范围切换；
- 提供位置选择入口，当前默认显示“福建·厦门”；
- 数据加载失败时显示错误状态；
- 使用 GitHub Actions 每 15 分钟抓取浙江省水利厅公开台风路径数据，并自动部署 GitHub Pages。

## 7. 基线发现与风险

### P0：信息可信度与安全边界

- 页面仍残留“演示页面”“演示路径图”“虚构台风”和 `OFFICIAL WARNING DEMO` 等静态演示文案，与实时数据状态冲突；
- 当前“白色提醒”来自上游字段，但页面需要更清楚地区分“来源系统状态”“本地官方预警”和“本站提示”；
- 数据延迟提示存在，但尚未形成明确的正常、延迟、失败、无活动台风状态体系。

### P1：移动端可用性

- 390 px 视口下首屏正文和黄色预警卡右侧被裁切，存在横向溢出；
- 顶部导航在移动端被隐藏后，关键信息入口的替代路径需要核验；
- 首屏信息密度较高，用户尚不能立即判断“对我所在位置有什么影响”。

### P1：产品价值表达

- 页面能回答“台风是什么、在哪里”，但对“与我是否相关、何时影响、我该做什么”的回答仍偏弱；
- “福建·厦门”目前更像静态界面状态，尚未证明真实定位或城市级影响计算能力；
- 路径图为自绘示意底图，地理参照、预测机构区别和不确定性表达需要加强。

### P2：作品集证明力

- 当前能证明数据接入、定时更新和前端可视化能力；
- 尚缺少完整的用户研究、指标定义、异常策略、可用性测试和优化前后对比证据。

## 8. 最终希望证明的产品能力

1. 能从高风险场景中提炼核心用户问题并建立清晰的信息优先级；
2. 能把权威数据转化为普通用户可理解、可行动的风险信息；
3. 能设计实时数据的更新、延迟、失败、回退和来源追溯机制；
4. 能处理定位、个性化影响、路径不确定性和安全边界；
5. 能通过埋点和用户测试验证设计，而不只完成视觉页面；
6. 能以完整案例说明问题、取舍、迭代过程和结果。

## 9. 后续总体验收标准

- 用户在首屏 10 秒内识别当前台风、数据时间、来源和自身相关性；
- 用户在 30 秒内找到所在地风险、预计影响时间和可执行建议；
- 实况、预测、预警和本站解释具有明确视觉与文案边界；
- 数据正常、延迟、失败、无活动台风四种状态均有可验证表现；
- 360 px 及以上移动视口无横向滚动或内容裁切，核心操作无需精细点击；
- 键盘路径、焦点、语义结构、对比度和动态内容提示通过专项检查；
- 核心页面达到可接受的加载性能，并支持弱网下的基本阅读与回退；
- 关键行为有事件定义，可用数据验证“是否更快理解并采取行动”；
- 作品集能展示 V1/V2 对比、关键决策、证据、结果和反思。

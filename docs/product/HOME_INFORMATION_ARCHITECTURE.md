# 海风哨首页信息架构

确认日期：2026-10-18  
状态：已确认

## 设计目标

首页不再要求用户通过经纬度、气压和路径图自行推断风险，而是优先回答：

1. 这场台风与我所在的城市是否相关；
2. 什么时候可能产生影响；
3. 我现在应该采取什么行动；
4. 这些信息是否权威、及时、可追溯。

## 模块顺序

新版首页采用以下顺序：

> 可信状态 → 本地影响 → 当前行动 → 台风概况 → 路径时间线 → 官方预警 → 专业数据 → 来源说明

## 1. 可信状态

页面顶部以克制的状态栏展示：

- 数据来源；
- 最后更新时间；
- 正常、延迟、中断状态；
- 安全说明入口。

正常状态不使用警告色。只有数据延迟、中断或来源异常时才提高视觉权重。

## 2. 当前关注城市

明确显示当前产品上下文：

- 当前关注城市：福建·厦门；
- 切换城市入口；
- 定位能力和授权状态。

在真实定位尚未实现时，不使用“已定位”等容易造成误解的表达。精确位置必须由用户主动授权。

## 3. 本地影响结论

该模块是首页视觉和信息中心，标题直接回答：

> 台风蔷琵目前是否影响厦门？

核心内容包括：

- 影响状态：暂未明显影响、需要关注、正在影响或暂无法判断；
- 台风中心与城市的距离；
- 接近或远离趋势；
- 预计主要影响时间；
- 当前本地官方预警；
- 结论对应的数据时间。

结论必须标注性质：官方发布、根据公开数据计算或暂时无法确认。数据不足时不得给出确定性判断。

## 4. 当前行动

紧随本地影响结论，展示不超过三条可执行建议：

- 此刻最重要的行动；
- 未来 24 小时需要关注的变化；
- 当前应避免的行为。

行动建议必须来源于适用地区的官方防御指南，不可仅根据台风强度自动生成。

## 5. 当前台风概况

将原英雄区压缩为摘要，展示：

- 中英文名称和编号；
- 当前强度；
- 中心位置；
- 最大风力和中心气压；
- 移动方向与速度；
- 实况时间。

经纬度不再作为首页最重要的视觉内容。

## 6. 路径与时间线

地图用于解释台风如何移动，必须回答：

- 台风从哪里来、向哪里去；
- 哪些点是实况，哪些点是预测；
- 每个关键节点对应什么时间；
- 路径预测由哪个机构提供。

模块包含：

- 实况路径与预测路径的差异化视觉；
- 文字时间线；
- 24、48、72 小时范围切换；
- 预测不确定性说明；
- 地图加载失败时的文字回退。

## 7. 本地官方预警

展示用户所选城市对应的官方预警：

- 预警名称与级别；
- 发布地区；
- 发布机构；
- 发布时间与有效状态；
- 官方原文入口。

在厦门本地官方预警数据尚未接入时，明确显示“暂未接入厦门官方预警数据，请前往官方渠道核验”。浙江省水利厅路径系统状态不得替代厦门本地官方预警。

## 8. 防御指南

根据已核验的官方指南，按用户行动阶段展示：

- 现在应该做什么；
- 影响前应该准备什么；
- 影响期间应该避免什么。

完整预警等级说明进入次级内容，不占据首页主要决策路径。

## 9. 专业数据

在首页后半部分展示风圈、风速、气压、经纬度等专业数据。默认只展示核心指标，其余内容可以展开查看。

## 10. 来源与方法

集中说明：

- 台风实况和路径来源；
- 本地预警来源；
- 距离、方向和趋势的计算方法；
- 更新频率；
- 延迟和异常处理；
- 产品安全边界。

## 移动端首屏要求

在 390 × 844 视口中，不滚动或仅轻微滚动即可看到：

1. 当前关注城市；
2. 台风与该城市的影响结论；
3. 数据更新时间及状态；
4. 本地官方预警状态；
5. 最重要的一条行动建议；
6. 查看路径入口。

核心内容不得横向溢出或被裁切。

## 主导航

- 本地影响；
- 台风路径；
- 官方预警；
- 数据来源。

## 必须支持的页面状态

| 状态 | 首页响应 |
| --- | --- |
| 有活动台风且可能影响本地 | 突出影响时间、官方预警和当前行动 |
| 有活动台风但暂不影响本地 | 明确说明暂未明显影响，保留持续关注入口 |
| 多个活动台风 | 默认展示与城市最相关的台风，并提供切换入口 |
| 无活动台风 | 展示当前安全状态、更新时间和历史台风入口 |
| 本地预警尚未接入 | 明确说明能力缺失，并提供官方核验入口 |
| 数据延迟 | 显示延迟时长，降低结论确定性，提供官方来源 |
| 数据加载失败 | 保留安全说明、官方链接和最近一次成功数据时间 |

## 验收标准

- 首页模块顺序符合已确认的信息架构；
- 首屏首先回答本地相关性，而不是首先展示专业气象指标；
- 用户可以区分官方信息、本站计算和未知状态；
- 移动端首屏包含城市、结论、时效、预警和行动；
- 所有已定义状态都有明确的内容策略；
- 不使用未接入的定位、本地预警或影响计算能力误导用户。
